# Paradox: эксплуатация

Установка, обновление, данные, CLI, лимиты и разбор проблем. Версия — **1.5.1**.
Как устроено внутри — `ARCHITECTURE.md`, что делает каждый модуль — `MODULES.md`,
планы — [TODO.md](../TODO.md).

## Установка

### Установщик (Windows)

1. Скачать `Paradox-1.5.1-setup.exe` со страницы
   [v1.5.1](https://github.com/v314xm/paradox/releases/tag/v1.5.1).
2. Запустить. SmartScreen предупредит, что издатель неизвестен: бинарник не
   подписан (почему — в [SECURITY.md](../SECURITY.md)) → «Подробнее» → «Выполнить в любом случае».
3. Inno Setup ставит приложение **для текущего пользователя**, без UAC:
   `%LOCALAPPDATA%\Programs\Paradox`. Языки — русский и английский, ярлык в
   «Пуск», ярлык на рабочем столе — по желанию.
4. В конце установщик предлагает запустить Paradox.

Установщик содержит только GUI. Консольной команды `paradox` в нём нет —
CLI ставится из Python-пакета (см. «Из исходников»).

### Портативная сборка (onedir)

Собранный каталог `dist\Paradox\` — это и есть портативная версия:

```text
dist\Paradox\
├── Paradox.exe
└── _internal\        # интерпретатор, PySide6, зависимости
```

Каталог копируется целиком, запускается `Paradox.exe`. Реестр не трогается,
права администратора не нужны, можно с флешки. Данные пользователя всё равно
пишутся в `%APPDATA%\Paradox` (см. ниже), а не рядом с `.exe` — перенос каталога
историю не ломает, но и не забирает.

### Из исходников

```bash
pip install -e ".[gui]"          # ядро + GUI
paradox capture.pcap             # CLI
python -m paradox_gui            # GUI
```

Python 3.11+. Для YARA и Threat Intel — `pip install -e ".[gui,yara,enrich]"`.

## Обновление

- **Установленная версия.** Закрыть Paradox, запустить новый `setup.exe`.
  AppId тот же, поэтому установка идёт поверх старой в тот же каталог.
  Настройки и история лежат в `%APPDATA%`, их обновление не трогает.
- **Портативная.** Заменить каталог `dist\Paradox\` целиком. Старый каталог
  сохранить, пока не убедишься, что новая версия работает.
- **Из исходников.** `git pull && pip install -e ".[gui]"`.

Перед обновлением достаточно сохранить три вещи: `history.db`,
`settings.json` и каталог плагинов.

## Удаление

Параметры → Приложения → Paradox → Удалить. Удаляется только каталог установки.

Остаются (удалять вручную, если нужно):

- `%APPDATA%\Paradox\` — история прогонов и настройки;
- `~/.paradox\plugins\` — пользовательские детекторы;
- каталог отчётов `reports\` — там же, где запускался разбор.

## Первый запуск

1. Перетащить `.pcap` в drop zone на вкладке «Прогон» (или «Файл → Открыть pcap»,
   `Ctrl+O`). Второй путь — «Открыть несколько pcap для слияния…»: 2+ файла
   склеиваются в один датасет, чтобы beaconing и slow-scan видели длинный горизонт.
2. Дождаться фаз разбора: прогресс идёт по этапам, а не по процентам пакетов.
3. Смотреть summary, findings, противоречия; вкладка «Код инжекта» покажет
   выдержки тел, на которых сработали детекторы инъекций и веб-шеллов.

По умолчанию профиль — Default, плагины выключены, обогащение не запускается.
GUI не пишет JSON и Markdown сам: результат живёт в текущей сессии и в
«Истории» (SQLite), а файлы сохраняются через «Файл → Экспорт» (JSON,
Markdown, flow report) и вкладку «Экспорт» (CSV, STIX, HTML). Единственное
исключение — IOC-файлы: пайплайн пишет их сам в `output_dir` после каждого
прогона.

## Где лежат данные

| Что | Путь | Примечание |
|---|---|---|
| История прогонов | `%APPDATA%\Paradox\history.db` | SQLite, хранится до 50 последних прогонов, внутри — полный JSON отчёта |
| Настройки GUI | `%APPDATA%\Paradox\settings.json` | переопределения `Config`, отключённые детекторы и правила, язык |
| Плагины | `~/.paradox/plugins/*.py` | `Config.plugins_dir`; включаются флагом `--plugins` или в «Настройки → Плагины» |
| Отчёты | `reports\` | `Config.output_dir`, относительный путь считается от рабочего каталога процесса; меняется в «Настройки → Отчёты» и флагом `-o` |
| IOC-файлы | тот же `output_dir` | `iocs.txt`, `iocs.csv`, `iocs.json`, `suricata.rules`, `queries.txt` |
| API-ключи Threat Intel | системный keyring (Windows Credential Manager) | в `settings.json` не попадают; вводятся в «Настройки → Threat Intel» |
| Лог падений GUI | `Paradox-error.log` рядом с `Paradox.exe` | в исходниках — в рабочем каталоге; append, при > 5 МБ обрезается до последних 2.5 МБ |

`%APPDATA%` — это обычно `C:\Users\<user>\AppData\Roaming`.
На Linux/macOS: `~/.local/share/Paradox/history.db`, `~/.config/Paradox/settings.json`.

Каталог `reports\` относительный не случайно: при запуске из «Пуска» рабочим
каталогом становится каталог установки, при запуске из консоли — текущий.
Если нужен предсказуемый путь, задать абсолютный в «Настройки → Отчёты».

## CLI

```bash
paradox capture.pcap                          # JSON + Markdown в reports/
paradox capture.pcap -o reports/today.json    # конкретный путь
paradox capture.pcap -o reports/              # директория
paradox capture.pcap --enrich                 # + Threat Intel
paradox capture.pcap --stix                   # + STIX 2.1 bundle
paradox capture.pcap --html                   # + HTML-отчёт (печать в PDF)
paradox capture.pcap --plugins                # + детекторы из ~/.paradox/plugins
```

Без аргумента `paradox` спросит путь к pcap интерактивно.

Правила имени файла: берётся имя pcap, точки заменяются на подчёркивания,
длина ограничена 80 символами (`snort_log.1425892283.pcap` →
`snort_log_1425892283_pcap`). Без `-o` отчёты идут в `output_dir`
(`reports/` по умолчанию), рядом с JSON пишется Markdown. С `-o`:

- путь без расширения → добавляется `.json`;
- существующая директория или путь с `\` / `/` на конце → внутрь кладётся
  `<stem>.report.json`;
- иначе — ровно указанный файл, `.md` / `.stix.json` / `.html` кладутся рядом.

Что появляется на диске:

- `<stem>.report.json` — полный отчёт: `schema_version`, `provenance`
  (версия инструмента, путь и sha256 pcap), `summary`, `entities`, `dns`, `flows`,
  `http`, `http_objects`, `carved_files`, `findings`, `contradictions`,
  `attack_graph`, `timeline`, `absence`, `ndp`, `ioc_files`;
- `<stem>.report.md` — TL;DR, timeline, findings, IOC;
- `<stem>.report.stix.json` — с `--stix`;
- `<stem>.report.html` — с `--html`;
- `iocs.txt`, `iocs.csv`, `iocs.json`, `suricata.rules`, `queries.txt` — всегда
  в `output_dir`, даже если `-o` указывает в другое место. Отключается только
  через `Config.ioc_export_enabled`.

`--enrich` требует сети, а для части провайдеров — ключей (keyring или
переменные окружения).
Если обогащение упало, отчёт всё равно пишется, а причина — в
`enrichment_stats.error`. Версию CLI печатает `--version`.

## Коды выхода

| Код | Когда | Статус |
|---|---|---|
| 0 | разбор завершён, отчёты записаны | реализовано |
| 2 | файл не найден; также ошибки разбора аргументов (`argparse`) | реализовано |
| 1 | трейсбек Python: обрезанный pcap, внутренняя ошибка | текущее поведение, не контракт |
| 3 | ошибка формата входа: не-pcap или `.pcapng` (`ParadoxInputError`) | реализовано |
| 4 | внутренняя ошибка | планируется, `TODO.md` 1.2 |

В скриптах можно проверять `0`, `2` и `3`; `1` и `4` — не контракт.

## Ограничения

| Что | Значение | Настройка |
|---|---|---|
| TCP reassembly на поток | 1 МБ | `tcp_reassembly_max_bytes_per_flow` |
| TCP reassembly суммарно | 200 МБ | `tcp_reassembly_max_total_bytes` |
| Тело HTTP-объекта | 1 МБ | `http_object_body_limit` |
| Распакованное тело (gzip/deflate) | 8 МБ | `http_body_max_decoded_bytes` |
| Вырезанный файл | 50 МБ | `file_carve_max_size` |
| Выдержка payload в отчёте | 64 КБ | `payload_excerpt_bytes` |
| Сообщений HTTP на поток | 200 | `http_object_max_messages_per_stream` |
| IOC на одно обогащение | 100 | `enrichment_max_iocs` |

Что из этого важно на практике:

- **200 МБ — общий бюджет на весь захват.** Когда он исчерпан, reassembly
  отключается до конца файла, и HTTP-детекторы, веб-шеллы и YARA по хвосту
  захвата молча не срабатывают (`TODO.md`, 1.4). Признаки в отчёте:
  `summary.tcp_streams` и `summary.tcp_streams_truncated`.
- **Формат — `.pcap`.** `.pcapng` не читается: `RawPcapReader` падает
  трейсбеком (`TODO.md`, 1.2). Конвертировать заранее (`editcap -F pcap`).
- **Память.** На 335 МБ / 627k пакетов пик — около 106 МБ RSS (см. README).
  Пропорционально растёт с числом потоков и объёмом reassembly.
- **pcap > 2 ГБ.** Stream mode нет (`TODO.md`, волна 3), файл целиком живёт
  в памяти. Многогигабайтные захваты разбираются по частям: разбить по времени
  (`editcap`), затем прогнать через GUI-слияние нескольких pcap или отдельными
  прогонами и сравнить отчёты на вкладке «Сравнение».
- **Слияние нескольких pcap** склеивает TCP-потоки одного 5-tuple из разных
  файлов; на этом месте возможны ложные веб-шеллы и YARA-срабатывания
  (`TODO.md`, 1.4). Для подозрительных пар лучше прогонять файлы отдельно.

## Как читать отчёты

### JSON

Машиночитаемый источник правды: `schema_version` (в 1.5.1 — `0.3.0`),
`provenance.pcap_sha256` для сверки захвата, `summary` со счётчиками и
`extractor_errors`, `findings[]` с `type`/`severity`/`confidence`/`evidence`,
`contradictions[]` с фактами и подсказкой. По нему работает вкладка «Сравнение»
и любые внешние скрипты.

### Markdown

Для чтения глазами и вставки в тикет: TL;DR в порядке kill-chain, timeline,
findings, IOC. Таблиц и цветовых акцентов нет — это для HTML.

### HTML

Самодостаточный файл со встроенным CSS, без JavaScript и без обращений в сеть:
сводка, findings по severity и confidence, противоречия с фактами, timeline,
IOC. Все значения экранируются, evidence показывается как JSON с обрезкой.
Открывается в любом браузере. PDF получается печатью: «Печать» →
«Сохранить как PDF». Нативного PDF-экспортёра в 1.5.1 нет — это единственный
штатный путь.

### STIX 2.1

Bundle с `indicator`-объектами для внешних IP и доменов из findings.
Внутренние (private) адреса в bundle не попадают — делиться ими бессмысленно,
поэтому на чисто внутреннем захвате bundle будет пустым. ID детерминированы
(UUIDv5 от типа и значения): повторный прогон того же pcap даёт тот же файл,
и diff не шумит. Импортируется в любую платформу, понимающую STIX 2.1.

### IOC-файлы

- `iocs.txt` — построчно, для grep и copy-paste;
- `iocs.csv`, `iocs.json` — для таблиц и скриптов;
- `suricata.rules` — правила IDS только по high/critical;
- `queries.txt` — готовые запросы KQL (Sentinel/Defender) и Splunk.

## Разбор проблем

### GUI упал или закрылся без сообщения

Смотреть `Paradox-error.log` рядом с `Paradox.exe` (в исходниках — в рабочем
каталоге). Файл в режиме append, каждый запуск отделён строкой `START ...`,
падения C-уровня помечены `Fatal Python error`, необработанные исключения —
`UNCAUGHT`. Приложить этот файл к issue.

### Отчёт пустой: 0 findings

Это не всегда баг. Проверить по порядку:

1. `summary.extractor_errors` в JSON (CLI печатает `extractor errors`, если
   счётчик не ноль) — если экстрактор падал, детекторы работали по пустым данным.
2. Профиль: Corporate выключает шумные детекторы, CTF наоборот снижает пороги.
3. Трафик: если в захвате нет DNS, TLS-хендшейков и HTTP (только бинарный
   обмен), большинству детекторов не на что смотреть.
4. Allowlist: CDN, DoH и Windows Update исключены по умолчанию.
5. Плагины: `--plugins` не передан или «Настройки → Плагины» выключены —
   пользовательский детектор не загружался. Ошибки плагина лежат в
   `summary.extractor_errors.plugin`.
6. Куда смотреть: CLI печатает фактический путь `report JSON`; в GUI отчёт
   лежит в текущей сессии и в «Истории».

Пустой STIX при непустом отчёте — норма: фильтр внешних IOC (см. выше).

### Антивирус ругается на выдержки payload

В отчётах лежат фрагменты тел HTTP, на которых сработали детекторы инъекций и
веб-шеллов, — это ровно те строки, которые антивирус считает сигнатурой. Чтобы
файлы на диске не карантинились, выдержка хранится в base64
(`evidence.payload_samples[].text_b64`), а читаемый текст GUI собирает в памяти
на вкладке «Код инжекта». Тем не менее Defender может пометить сам отчёт,
`Paradox.exe` или инсталлятор.

Что делать:

- не отключать защиту целиком — добавить в исключения каталог отчётов и каталог
  установки;
- проверить, что файл взят с релизной страницы GitHub, а не из пересылки;
- если антивирус удалил отчёт — перегенерировать прогон, сузив
  `payload_excerpt_bytes` или выключив `payload_excerpt_enabled`;
- ложное срабатывание на `.exe` сообщать в issue: приложить имя детекции и хеш.

### Прогон идёт неожиданно долго

Проверить `summary.tcp_streams` и размер захвата: reassembly до 200 МБ и
HTTP-разбор — самая дорогая часть. На больших файлах помогает отключить
`tcp_reassembly_enabled` (детекторы по HTTP и веб-шеллам при этом не работают)
или разбить захват. Ориентиры из README: 152 МБ / 232k пакетов ≈ 12 с,
334 МБ / 627k ≈ 23–28 с (замер 2026-11-10).

## Плагины: предупреждение

Плагин — обычный Python-файл, который исполняется в процессе Paradox с правами
пользователя. Это не песочница: плагин может читать файлы, ходить в сеть и
делать всё, что может запущенная от твоего имени программа.

- по умолчанию плагины выключены (`plugins_enabled=False`);
- включаются явно: `--plugins` в CLI или «Настройки → Плагины» в GUI;
- каталог по умолчанию — `~/.paradox/plugins`, менять только осознанно;
- запускать чужие плагины — то же, что запускать чужой скрипт: сначала прочитать.
